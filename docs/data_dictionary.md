# Data dictionary

All names use `snake_case`; timestamps are ISO-8601 UTC strings ending in `Z` when generated by the mock source. IDs are deterministic source identifiers, not randomly generated pipeline IDs. Every pipeline execution has a UUID `run_id`.

| Table | Grain / primary key | Important columns and rules |
|---|---|---|
| `customers` | One current row per `customer_id` | `email`, `created_at`, `status`; email must contain `@`; status is `active` or `inactive`. |
| `orders` | One current row per `order_id` | `customer_id` FK to customers; `amount >= 0`; supported currencies USD/EUR/GBP/INR; status in created/paid/shipped/cancelled; current row only advances to equal or greater `event_version`. |
| `order_events` | One row per `(order_id, event_version)` | Immutable event history; unique composite key prevents duplicate event ingestion. |
| `quarantine` | One rejected record occurrence | Includes `run_id`, entity, source page, record key if present, reason, original JSON payload and rejection timestamp. |
| `raw_pages` | One raw page per `(run_id, entity, page)` | Retains exact parsed JSON response and HTTP status in SQLite; matching JSON files are also written to `data/output/raw/`. |
| `checkpoints` | One row per entity | Highest fully committed page; page processing and checkpoint update are committed together. |
| `pipeline_runs` | One row per `run_id` | Status, timestamps, input/output/rejected counts, page count, duration and failure reason. |

## Relationships and business rules
- `orders.customer_id` references `customers.customer_id`; customer ingestion completes before orders begin.
- `order_events` preserves versions; `orders` is the current-state projection.
- Missing required fields, invalid types/values, unknown customer references, duplicate primary keys within a page, and stale out-of-order versions are quarantined with the source payload.
- A duplicate event version already in `order_events` is ignored by its composite primary key. Source records are synthetic and do not contain personally identifying information.
- `source_run_id` and `source_page` are included on current target records for lineage.
